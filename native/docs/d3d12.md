# D3D12 GPU output

## Usage

Create a shared 2D texture and a shared `ID3D12Fence` on the same adapter as
the engine. Query the borrowed device and queue with
`mt_engine_d3d12_info`, import the texture with
`mt_engine_import_d3d12_image`, import the fence with
`mt_engine_import_d3d12_timeline`, then call `mt_render_export_gpu` and poll
with `mt_engine_gpu_poll`. The Windows example
[`examples/d3d12-export-host.c`](../examples/d3d12-export-host.c) demonstrates
HDR and depth textures, fence reuse, bounded polling and readback comparison.

## Options

The output kind selects HDR, depth, center-depth or display conversion. HDR is
`R32G32B32A32_FLOAT` or `R16G16B16A16_FLOAT`; depth and center-depth are
`R32_FLOAT` or RGBA32F; display is `R8G8B8A8_UNORM`. A host-ready fence/value
may be supplied before the strictly increasing done fence/value. Reusing a
timeline requires a larger value; rejected calls do not touch either fence.

## Caveats

Only same-adapter, shared DEFAULT-heap, single-sample, one-mip UAV textures are
accepted; buffer import is not supported. The host state tracker must declare
the imported texture COMMON before the first export. The current tracker leaves
the texture COMMON after accepted export work; after a host readback transition
from COMMON to COPY_SOURCE, restore COMMON before signaling a ready value for a
later export. Keep resources, NT
handles and fences alive until the export is retired and destroy import
wrappers before closing them. `BUSY` and device removal require retry or device
recreation; a device-removed outcome is never reported as successful completion.
