# D3D12 GPU output

The Windows SDK accepts a foreign `ID3D12Resource` and shared NT fence for
zero-copy output. The resource and fence must be created for the same underlying
device as the engine. The library owns only the wgpu wrapper and never closes
the host's resource/fence handles; native queue waits/signals use the imported
fence values.

The planned zero-copy path requires a same-adapter device, a shared texture (or
buffer fallback), and two shared `ID3D12Fence` objects. The library would wait on
the host-ready fence, write color/depth, signal the done fence, and retain the
resource until GPU retirement. Cross-adapter handles, mismatched formats,
multi-sample resources and untracked state are rejected before touching the
handles. Device removal makes the result unknown and requires rebuilding both
devices.

wgpu 30's DX12 HAL `raw_device`, `texture_from_raw` and `buffer_from_raw` are
used for the resource wrapper. The fence is deliberately kept as a raw native
handle because wgpu has no public external-fence object; wait/signal ordering is
encoded on the native queue. Cross-adapter handles, mismatched formats,
multi-sample resources and untracked state are rejected before touching them.
