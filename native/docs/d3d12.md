# D3D12 GPU output

The Windows SDK accepts a foreign `ID3D12Resource` and shared NT fence for
zero-copy output. The resource and fence must be created for the same underlying
device as the engine. Query that device with `mt_engine_d3d12_info`. The
library owns only the wgpu wrapper and never closes the host's NT handles;
native queue waits/signals use the imported fence values.

The zero-copy path requires a same-adapter device, a shared texture (or buffer
fallback), and one shared done `ID3D12Fence` plus an optional host-ready fence.
When supplied, the library waits on the host-ready fence, writes
HDR/depth/display data, signals the done fence, and
retains the resource until GPU retirement. Cross-adapter handles, mismatched
formats, multi-sample resources and non-UAV resources are rejected before
touching the handles. The host remains responsible for correct D3D12 resource
state tracking. Device removal makes the result unknown and requires rebuilding
both devices.

wgpu 30's DX12 HAL `raw_device`, `texture_from_raw` and `buffer_from_raw` are
used for the resource wrapper. The fence is deliberately kept as a raw native
handle because wgpu has no public external-fence object; wait/signal ordering is
encoded on the native queue. `mt_render_export_gpu` supports HDR, depth,
center-depth and display conversion, timeline reuse, and nonblocking polling.
Rejected calls leave both fences untouched; accepted work survives cancellation
and resize, while `BUSY` and `UNAVAILABLE` require the host to keep its native
objects alive until the outcome is drained or the device is rebuilt.
